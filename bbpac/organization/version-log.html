Version Log

Every determination, boundary, and document behind the Bongo Beach formation effort, live from the database — and every change to any of it, permanently, in order. Nothing here is ever edited in place or deleted. It is only ever versioned. The full cross-department checklist this ledger tracks lives at the Master Due-Diligence Matrix.

This page reads directly from the same database that tracks Track A (park classification) and Track B (PAC formation). Nothing is staff-only here — the same public transparency this whole formation effort asks of the Chicago Park District, it holds itself to first.

How this stays honest. Every table below has exactly one way a row can change: a database trigger that fires on every insert or update and permanently snapshots the full new state into the ledger before anything else happens. There is no code path — staff tool, admin panel, or direct database edit — that can change a record without also writing its version. Updating a record and covering your tracks are, by construction, the same number of steps: infinite.
